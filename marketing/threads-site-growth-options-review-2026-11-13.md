# 「Threads·GameDil 활성화 제안 — 2026-11-13」 검토 (Claude)

## 결론
- 방향은 맞다(새 슬롯 추가 대신 기존 게시 교체, 게시물 약속=도착 페이지, 사이트 개편 분리, 원시 건수 비교). 착수 가능.
- 다만 아래 3가지를 정하고 시작해야 한다.

## 사실 확인
- 사이트 기존 경로: under-10000.html·korean-demo.html 200, shared-games.html 200·noindex(제안 내용과 일치). 공유 목록은 `/shared-games.html#ids=a,b,c` 형식이라 `?utm_...#ids=...`로 UTM과 함께 3선 직결 가능 → 첫 주 사이트 개편 없이 "3선" 도착 페이지 해결.
- 픽 게시 UTM은 auto_daily_pipeline.py:562에서 복구돼 있음.
- 외부 댓글 상한 20: `browser_outreach.py` DAILY_LIMIT=20(파일 수정 11/13 02:45). 실제 발행은 11/8~12 하루 37~44건이었으므로 20은 오늘부터 적용되는 값이다. "기존 20건 유지"가 아니라 "오늘 45→20 축소"로 기록해야 비교가 맞다.
- 제안에 없는 자동 행동: PROACTIVE_FOLLOW_DAILY_LIMIT=25(자동 선팔로우). 댓글 20 + 팔로우 25가 같은 기간에 돌므로 성과 비교 시 변경 요소로 표시 필요.

## 정해야 할 것
1. 취향 상담 답변 주체: 자동 inbound-reply가 3개 후보를 생성하면 없는 게임·틀린 가격 위험. GameDil DB/공개 JSON에서만 후보를 뽑고(한국어·가격 확인일 2일 이내), 사람이 보고 보내는 반자동을 권장. 답변 시한(예: 12시간)도 정할 것.
2. UTM 이름 규칙: 형식별 utm_campaign 고정(예: taste_consult / data_pick3 / dev_demo), utm_content=날짜. 지금 정하지 않으면 2주 비교가 불가.
3. 교체 대상 슬롯: 어떤 기존 게시(뉴스 글 권장 — 복붙 티·저작권 위험이 가장 큼)를 빼고 넣을지 명시.

## 보완 제안
- 개발자 데모 체험: 소개 전에 개발자 본인 동의·링크 확인. 기존 스포트라이트와 같은 슬롯으로 합쳐 주1회로.
- 데이터 3선: 기준 하나 + 확인 시각 표기 좋음. 할인 0%·가격 확인일 2일 초과 게임 자동 제외(11/7 사고 재발 방지)를 조건에 명시.
- 측정: GameDil의 통합 분석(data-site 스크립트) 연결 여부와 GA4 중 어느 쪽 숫자를 기준으로 할지 하나로 고정.
