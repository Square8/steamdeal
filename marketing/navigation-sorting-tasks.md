## Gemini 구현 — build.py, theme.py, 필요한 selftest.py 변경

### A. 홈 메뉴 일관성
- 홈에서 지금 인기 #popular, 최근 인하 #drop, 핫딜 #hot, 기대작 #soon, 데모 #demo, 1만원 이하 #under-10000, 전체 #all로 이동.
- / 및 /index.html 모두 같은 페이지 내 이동. 기존 q/UTM 등 쿼리를 잃거나 페이지를 불필요하게 다시 로드하지 않게 한다.
- 상세/랜딩/개인 페이지에서는 홈의 해당 앵커로 연결. 404의 깊은 경로에서 루트 링크도 유지.
- 비교/내 찜은 독립 기능이므로 해당 페이지 링크 유지.
- 모든 메뉴 대상 섹션은 빈 데이터에서도 존재. 최근 인하가 없으면 짧은 빈 상태 제공(기존 섹션 미생성 테스트는 새 요구사항으로 갱신).
- 홈에 1만원 이하 미리보기 최대 8장 추가. 필터는 기존 under-10000 랜딩과 동일: 성인 제외, 한국어, 현재 유료 가격 0원 초과~10,000원 이하. 임의 대상 확대 금지.
- 기존 섹션 순서는 가급적 유지하고 신규 1만원 이하를 데모 뒤에 배치. 각 '○○ 전체'는 기존 랜딩 URL 유지.
- 랜딩의 홈 복귀 링크 '전체 보기'는 '홈으로 돌아가기'처럼 목적지 명확한 문구로 바꾼다.

### B. 제목 가림 해결
- sticky 헤더의 실제 높이 + 약 16px 여유로 앵커 오프셋 계산. ResizeObserver 등으로 헤더 줄바꿈/화면 크기/글꼴 로딩 변화 반영. CSS 변수와 공통 코드 1곳으로 관리하고 JS 미실행 기본값 제공.
- scroll-padding과 scroll-margin을 중복 적용해 과한 공백이 생기지 않게 한다.
- 클릭뿐 아니라 #popular 등 직접 진입, 새로고침, 다른 페이지에서 진입도 제목이 보이게 한다. 초기 측정 전에 앵커 이동된 경우 필요할 때만 보정, 사용자가 움직인 뒤 강제 점프 금지.
- 제목 자체의 줄바꿈도 허용. 모바일·확대에서 제목/개수/전체 링크가 겹치거나 잘리지 않게 한다. reduced-motion 설정 존중.

### C. 모든 LANDINGS 페이지에 공통 정렬
- 제목/설명 아래, 카드 위에 동일한 정렬 UI와 표시 개수. 기본순 / 평가 좋은 순 / 리뷰 많은 순 / 낮은 가격순 / 높은 가격순 / 할인율순 / 이름순.
- 기본순은 각 랜딩 기존 서버 순서 그대로 보존(인기 동접순, 기대작 출시일순 등). 현재 정렬 설명이 바뀌면 기존 '리뷰 많은 순' 같은 고정 안내와 모순되지 않게 한다.
- 평가순: 유효 리뷰수>0인 게임의 긍정률 내림차순 → 리뷰수 내림차순 → 이름 → appid. 등급 문자열 사전순 정렬 금지. 평가 미정은 마지막. '긍정률 기준, 동률은 리뷰 수' 안내.
- 리뷰순: 유효 리뷰수 내림차순, 결측 마지막. 이름/appid로 동률 결정.
- 가격순: 명시적 무료는 실제 0원으로 취급. 유료 양수 가격과 함께 오름/내림차순. 가격 미정/출시 전 미가격은 양쪽 모두 마지막. 값 없는 게임을 무료로 변환 금지.
- 할인율순: 유효 할인율 내림차순, 미확인 마지막. 이름/appid로 동률 결정.
- 데모 랜딩은 '가격·할인은 본편 기준이며 데모는 무료입니다' 설명. 단독 demo 앱은 본편 가격을 추정하지 않고 무료 체험/가격 정보 의미를 보존한다.
- 이미 서버 렌더된 카드에 최소한의 안전한 data 속성을 부여하고 DOM 노드를 재배열하는 방식 우선. 전체 검색 JSON 추가 fetch, 전체 데이터 중복 인라인, innerHTML 데이터 주입 금지.
- 해당 카테고리 후보만 정렬. 기존 찜 버튼 작동/포커스 보존. aria-label, 키보드 조작, 변경 결과 aria-live 등 접근성 제공.
- sort 쿼리로 선택 유지/새로고침/뒤로가기 복원. 기존 UTM/q/다른 파라미터/해시 보존, 기본값이면 sort만 제거. 잘못된 sort는 기본순. canonical은 기존 쿼리 없는 주소 유지.
- 기존 최근 인하 120개 제한이 실제 어느 단계에 적용되는지 확인. 이번에 몰래 상한 확대/제거하지 말고 제한된 목록이면 표시 개수/설명에 명시. 다른 페이지도 표시된 목록 범위를 전체 DB인 것처럼 표현하지 않는다.
- 홈 #all의 기존 정렬 UI는 새 공통 메뉴와 용어/평가순/높은 가격순/리뷰순을 맞춘다. 기존 검색 일치 우선순위 정책은 유지하고 동률 정렬로 연결. 별도 변경을 개인 페이지에 확대하지 않는다.
