# Threads·GameDil 활성화 제안 — 2026-11-13

- 범위: 추가 활성화 방법에 대한 제안. 코드·예약·자동 운영 기준 변경이나 외부 게시 없음. 기존 제미나이 운영 유지.
- 확인: 프로젝트 지침/최근 인계, 11/08~09 성과 보고서, 현재 로컬 build.py의 찜·공유·목표가, 공개 사이트 및 Meta/Google 공식 안내.
- 주의: 과거 성과 보고서의 댓글 품질·성장 원인 단정은 이번 근거로 사용하지 않는다. 개발자 소개 답글/리포스트 및 유입 기록도 작은 과거 표본이며 원본 통계는 재조회하지 않았다.
- 웹 검색 도구의 일부 카테고리 페이지는 과거 크롤링본(10월 갱신 표기)이므로 현재 게임 수·가격·배포 상태 근거로 사용하지 않는다.

## 우선 실험: 기존 기능으로 대화→선정→방문 연결
1. 주1회 ‘취향/예산 상담’: 예산·좋아한 게임·피하고 싶은 요소를 댓글로 받는다. 구체적인 요청에만 근거 있는 3개 후보를 답하고 기존 찜 공유 목록으로 연결한다. 예문과 실제 운영 글을 구분하고 자동 댓글 수량 채우기 금지.
2. 주1회 ‘개발자 데모 체험’: 자발적으로 제출한 실제 게임의 데모/장면/개발자가 궁금한 점 하나를 소개한다. 타격감·난이도를 해보지 않고 평가하지 않는다. 결과로 실제 이용자가 남긴 피드백을 다음 소개에 연결하되 인용/재사용 범위를 확인한다.
3. 주1회 ‘데이터로 고른 3선’: 최근 가격 인하, 한국어 무료 데모, 전체/최근 평가 차이 중 확인 가능한 기준 하나로 선정. 각 게임의 구체적 특징+선정 이유+확인 시각을 제공. 할인 종료/출시 정보 등 없는 필드는 추정하지 않는다.
- 새 슬롯을 계속 추가하지 않고 기존 게시 일부를 위 형식으로 교체하는 2주 시험을 제안한다. 실행 전 실제 게시 일정을 정할 때 기존 예약을 보존한다.
- 첫 주는 사이트 개편 없이 기존 상세/1만원 이하/데모/찜 공유 링크로 시험한다. 사이트 개편은 후속 주에 분리하여 비교한다.

## 사이트 쪽 우선순위
- 1순위: 게시물의 약속과 도착 페이지 일치. ‘추천3개’면 선정3개, 특정 게임이면 상세, 1만원 목록이면 해당 목록으로 연결한다. 공통 홈 링크로 보내지 않는다. 게시 형식별 UTM으로 구분한다.
- 2순위: 반응이 나온 주제만 작은 공개 모음집으로 만든다. 예: ‘한국어 데모3선’, ‘이번 주 1만원 이하3선’. 포함/제외 기준·추천 이유·주의점·갱신일을 제공한다. 없는 플레이 경험은 쓰지 않는다.
- 기존 찜 공유는 개인 공유 용도(noindex)이다. 검색 유입용 편집 모음집은 별도 공개 URL이 필요하다. 인원수/플레이시간 같은 선정 조건은 원천 데이터 검증 후 사용한다.
- 3순위: 공유 목록 제목·미리보기·저장 진입을 개선한다. 이미 있는 찜/공유 기능을 새 기능으로 중복 구현하지 않는다.
- 이후: 사용자가 동의한 목표가 도달 알림을 검토한다. 현재 목표가는 이 기기 브라우저 저장/재방문 표시이며 푸시가 아니다. 실제 알림은 서버 저장·동의·구독해지·중복 방지 운영이 필요한 별도 과제다.
- 검색 확장은 검증된 소수 주제부터. 비슷한 AI 글을 대량 생성하기보다 선정 근거와 최신 정보를 갖춘 페이지를 만든다.

## 판정
- 기존 외부댓글 상한20건을 유지한다. Threads는 운영자 답글을 뺀 실제 참여자 수·구체적 요청/후기·리포스트, 사이트는 UTM 방문·Steam 이동·가능한 경우 찜 행동을 본다.
- 세션/이벤트/사람 수를 혼동하지 않고, Steam 이동을 구매로 해석하지 않는다. 현재 측정되지 않는 찜·재방문 수치는 만들어내지 않는다.
- 2주 후 게시물당 중앙값과 원시 건수를 함께 비교한다. 각 형식2~3회는 방향성 확인용이며 통계적 성공 판정이나 알고리즘 효과 입증으로 쓰지 않는다.
- 우선 착수 제안: 취향 상담1개 + 근거 있는3선1개 + 기존 목록 직결. 실제 외부 게시 및 운영 변경은 이번 요청에서 실행하지 않았다.
